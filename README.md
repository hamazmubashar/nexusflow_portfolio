# NexusFlow Autopilot

Automation platform for NexusFlow Systems (synthetic): ITSM triage and RAG copilot, seat-expansion governance, invoice reconciliation.

## Layout

| Path | Contents |
|---|---|
| `backend/app/{api,core,models,services}` | FastAPI backend. `core/ingest_data.py` loads the seed data |
| `backend/tests` | pytest suite (`pytest.ini` lives in `backend/`) |
| `database/seed_data` | Seed copy of `schema.sql`, the 9 CSVs and `manifest.json` used by ingestion |
| `database/init` | First-boot Postgres scripts (pgvector, n8n database) |
| `database/` | `schema.sql` and `generate_nexusflow_data.py`, the source of truth |
| `nexusflow_csv/` | Generator output (source of the seed copy) |
| `nexusflow_documents/` | Unstructured corpus (SOPs, legal, correspondence) for RAG in Stage 2 |
| `docs/` | Company Specification and Problem Blueprint |
| `n8n_workflows/` | Exported n8n workflows, mounted in the container at `/workflows` |

## Quick start

```bash
cp .env.example .env        # then set POSTGRES_PASSWORD, N8N_ENCRYPTION_KEY, GEMINI_API_KEY
docker compose up -d
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.core.ingest_data --reset
.venv/bin/python -m pytest
```

n8n: http://localhost:5678, or whatever `N8N_HOST_PORT` is set to in `.env`. On this machine it's 5679 because FlowPilot already uses 5678.

If you regenerate the data with `database/generate_nexusflow_data.py`, copy the new CSVs and `schema.sql` into `database/seed_data/` again.

## Stage 2: RAG engine

Code is in `backend/app/services/rag/`: `chunking.py` → `embeddings.py` → `ingest.py` → `retriever.py` (hybrid RRF) → `copilot.py` (Gemini, verified citations). The table definition is in `database/migrations/001_document_chunks.sql`. Ingestion applies it automatically.

```bash
cd backend
.venv/bin/python -m app.services.rag.ingest          # incremental; --force re-embeds everything
.venv/bin/python -m pytest -m "not live"             # offline + DB tests, no API calls
.venv/bin/python -m pytest                           # also runs the live Gemini tests
```

Rows are tagged with their embedding model (`gemini/gemini-embedding-001@768` by default), and retrieval only compares vectors within one model. With `EMBEDDING_PROVIDER=local`, ingestion uses `BAAI/bge-base-en-v1.5` through fastembed (`pip install fastembed`). That path is offline but untested so far.

## Stage 3: n8n automation and webhooks

FastAPI (`backend/app/main.py`, port **8010**, because FlowPilot's gateway already proxies host port 8000) and n8n authenticate each other with HMAC-SHA256 in both directions: `X-NexusFlow-Signature: sha256=HMAC(WEBHOOK_SIGNING_SECRET, "<X-NexusFlow-Timestamp>.<raw body>")`, with a 300 s replay window. Every event is recorded in `automation_events` (`database/migrations/002_automation.sql`), and a replayed `event_id` returns the stored result instead of running again.

| Route | Called by | Does |
|---|---|---|
| `POST /api/v1/webhooks/tickets/escalate` | ITSM / n8n | Applies the SOP-01 SLA clocks (24×7, coverage or business hours, in America/Chicago) and escalation thresholds. P1/P2 tickets, or any ticket with `request_copilot`, are dispatched to n8n |
| `POST /api/v1/webhooks/seats/request` | n8n | Applies the SOP-02 rolling 30-day aggregate and the $500/month rule, and records the request in `seat_requests`. Never provisions seats |
| `POST /api/v1/webhooks/invoices/delinquent` | n8n | Builds an account summary and a collection-notice **draft** (MSA §6, 15-day cure period). The draft is never sent |
| `GET /api/v1/webhooks/invoices/overdue` | n8n schedule | Lists overdue invoices for polling |
| `POST /api/v1/webhooks/n8n/callback` | n8n | Logs what each workflow run did |
| `POST /api/v1/copilot/ask` | n8n | Stage 2 RAG copilot |

Workflows are generated by `n8n_workflows/build_workflows.py`. Edit that file, not the JSON:

```bash
backend/.venv/bin/python n8n_workflows/build_workflows.py
docker exec nexusflow-n8n n8n import:workflow --separate --input=/workflows
for id in nxfP1TicketEscal1 nxfSeatExpansion1 nxfDelinquentInv1; do docker exec nexusflow-n8n n8n publish:workflow --id=$id; done
docker restart nexusflow-n8n
cd backend && .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8010
.venv/bin/python -m pytest -m "not e2e and not live"    # offline + DB; e2e needs uvicorn + n8n up
```

Set `NEXUSFLOW_ALERT_WEBHOOK_URL` (a Slack incoming webhook, or Discord with `NEXUSFLOW_ALERT_FORMAT=discord`) to have the P1 workflow actually post its alert. When it's empty, the alert is formatted and logged but not posted. `N8N_DISPATCH_MODE=mock` keeps every outbound event in memory, for offline work.

## Stage 4: governance agent and human-in-the-loop approvals

`backend/app/services/agents/governance_agent.py` is a deterministic state machine: INITIATED → ANALYZING_CONTRACT → CALCULATING_IMPACT → (APPROVED | WAITING_FOR_APPROVAL | REJECTED) → EXECUTED, with FAILED reachable from any non-terminal state. Each transition is committed to `governance_runs` (`database/migrations/003_governance.sql`), so a run survives an API restart and resumes from the database.

A human (the Finance Director, EMP-0082) must decide whenever any of these applies:
- the 30-day aggregate is over $500.00/month;
- the request isn't an explicit PURCHASE;
- the customer has their own legal documents in the RAG corpus (for example CUST-0040's SOW);
- the contract review failed;
- the corpus isn't indexed.

The Stage 2 copilot reviews any customer-specific documents. Its answer is advisory: it goes on the approval card, and it can't remove a reason or approve anything. Requests that violate a rule (delinquent customer, wrong contract, plan-tier crossing) are rejected by the agent. Seats and ARR change only in EXECUTED: one transaction, with the rows locked, never twice for the same request.

| Route | Purpose |
|---|---|
| `POST /api/v1/agents/governance/runs` | Start a run (signed `seat.requested` event). 201 = new run, 200 = same request_id resubmitted |
| `GET /api/v1/agents/governance/runs/{run_id}` | Run state, history, impact, decision (signed GET) |
| `GET /api/v1/approvals/pending` | Operator queue (signed GET). Expires stale items as it reads |
| `POST /api/v1/approvals/{token}/action` | `{"action": "APPROVE"/"REJECT", "approver_id", "comment", "approver_signature"}`. The token is the credential. If HMAC headers are sent (the n8n relay), they must verify too |

Approval tokens are `v1.<claims>.<HMAC>`, bound to one approval, one request, one approver and an expiry (default 72 h). They're single use, and only their SHA-256 is stored. n8n workflow 4 (`hitl_approval_notification_workflow.json`, id `nxfHitlApproval1`) posts the approval card to the channel without the token, builds a private payload for the approver, and relays signed decisions from `nexusflow/approval-decision` to the API. n8n still keeps the token in its execution data until `EXECUTIONS_DATA_MAX_AGE` prunes it.

## Stage 5: production API layer

The single entrypoint is `backend/app/main.py`, and every route is mounted under `/api/v1` by `app/api/v1/router.py`. The OpenAPI spec is at `/openapi.json`, with interactive docs at `/docs`.

- **Errors:** every error is RFC 7807 `application/problem+json`: `{type, title, status, detail, instance, code, request_id, …}`. Clients should branch on `code`; `detail` is for humans.
- **Tracing:** each request gets an `X-Request-ID` (yours, or a new UUID). It's echoed back, included in every problem body, and on every JSON log line.
- **Auth:** users send `Authorization: Bearer <JWT>` (HS256). n8n and other services keep using the HMAC signature and are treated as `SERVICE`.

| Role | Can |
|---|---|
| OPERATOR | read analytics/metrics, copilot ask/search, start and inspect agent runs, view the approval queue |
| MANAGER | everything OPERATOR can, plus decide approvals **as themself** (the JWT `sub` must equal `approver_id`, and the token binds the assigned approver) |
| ADMIN | everything MANAGER can. ADMIN still can't decide an approval assigned to someone else |
| SERVICE | n8n via HMAC: webhooks (HMAC only), copilot, agent runs, the queue, relayed decisions |

```bash
cd backend
.venv/bin/python -m app.core.security issue-token EMP-0082 MANAGER        # dev JWT for Parker Kim
curl -s localhost:8010/health | python3 -m json.tool                       # public: DB, pgvector, n8n, Gemini
curl -s localhost:8010/api/v1/analytics/dashboard -H "Authorization: Bearer $TOKEN"
```

`GET /health` returns 200 `ok`/`degraded`, or 503 `down` when PostgreSQL is unreachable. The n8n and Gemini probes are cached for `HEALTH_CACHE_SECONDS`. `GET /api/v1/metrics` returns compact KPIs, and `/api/v1/analytics/{dashboard,activity,sla}` feeds the Stage 6 UI.

## Stage 6: LangGraph, LangChain and the operator console

- **Governance agent on LangGraph.** `app/services/agents/langgraph_governance.py` is a compiled `StateGraph` with five nodes: `analyze_contract`, `check_rag_compliance`, `calculate_impact`, `wait_for_approval` and `execute_mutation`. `governance_runs` stays the checkpoint, and every node commits before the next runs. The diagram and node table are in [docs/governance_langgraph.md](docs/governance_langgraph.md). Each run records `engine: langgraph` and its `graph_trace`.
- **Copilot as a LangChain LCEL chain.** `app/services/rag/langchain_copilot.py` is built from a `BaseRetriever` over hybrid search, a `ChatPromptTemplate`, Gemini with `with_retry`/`with_fallbacks`, a `PydanticOutputParser` and quote verification. It's the API default (`COPILOT_ENGINE=langchain`), and `native` keeps the original. Both use the same prompt, schema and checks.
- **Approver decision tokens.** `POST /api/v1/approvals/{id}/decision-token` gives the signed-in *assigned* approver (MANAGER JWT) a token that's valid for up to 10 minutes and never stored, for use on `/approvals/{token}/action`. The n8n-delivered link token is still never exposed.
- **Operator console** (`frontend/`, Streamlit): Overview, Approvals, Copilot and Diagnostics, on live API data only.

```bash
cd frontend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh                                  # http://localhost:8502, opens at the login gate
# "Explore the demo" = read-only visitor. To review as Parker Kim (EMP-0082, MANAGER), paste the token from:
#   backend/.venv/bin/python -m app.core.security issue-token EMP-0082 MANAGER
.venv/bin/python -m pytest                # client + AppTest against the API on :8010
```
